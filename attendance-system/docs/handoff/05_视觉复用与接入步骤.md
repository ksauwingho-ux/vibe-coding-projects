## 接入步骤

1. npm ci，运行 dev，保存工作台与详情基线。确认源码目录与目标 Comate 工程的合并策略；本包不是自动覆盖已有后端工程的脚本。
2. 抽离组件，视觉回归不变。现有工程已有后端时先读其认证、路由、业务 ID 和 API 客户端，优先对接，不另起平行系统。
3. 新建统一数据 provider 接口；mock 只在明确演示模式启用。真实模式失败不得静默切回 mock。
4. 建立 six-state 样例与错误场景；实现空状态、首次加载、刷新旧数据标记、权限不足、同步中和失败重试。
5. 接身份与授权，再接查询分页、详情与汇总；记录字段映射和数据水位。
6. 接受控核对/申请动作，再接持久化查询；前端不直接更新底表最终值。
7. 接 Excel 预览与批次；后续 API 采集沿用批次与来源版本，不改页面业务模型。
8. 接导出和原生申请入口；校验 WPS 内嵌/跳转的实际登录态传递能力，不预设 SDK。
9. 根据角色扩展个人页、请假申诉、管理任务；用已有实施包的全链路验收，最后试点。

## 配置与部署

- 环境至少区分 demo/test/production；生产构建不打包可启用的真实凭证或模拟身份后门。
- 只把应用公开配置交给 Vite 客户端；WPS 应用密钥、长期令牌和审批回调验真凭证放后端受控配置。
- base path、同源 BFF/跨域方案、登录回跳、平台应用 ID、域名均待学校运行环境确认。
- 本包 Worker 是静态托管壳，不等于 API 服务。真实集成还需要授权执行、任务持久化、调度和日志归属。
- 不默认引入 SQLite 或第二套学生密码，保留多维表格主台账路线；平台能力不足要有实测证据和方案评审。

## 检查重点

首次进入不闪现他人数据；快速换筛选不被旧响应覆盖；弹窗可键盘关闭与聚焦；必填说明有清楚反馈；提交中防重复，失败保留草稿；长姓名/长课程不挤坏操作；手机详情与表单能完成主流程；明确“处理中”与“已完成”。未来真实 API 接入后重新做 UI 和业务检查，不沿用旧 passed 作为新版本证据。
