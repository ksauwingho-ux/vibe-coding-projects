# 业务规则与状态管理

详细规范在 baseline/02、03；本文件解释前端如何落地并指出原型不能直接复用的行为。基线中的“待业务确认”仍然待确认，本次补文档不将其变成已批准政策。

## 1 六类结果及展示

| final_judgment | 推荐标签 | 交互方向 |
|---|---|---|
| 正常 | 正常 | 查看来源与历史，不因正常自动开放改判 |
| 旷课 | 旷课 | 按权限申诉/辅导员复核 |
| 迟到 | 迟到 | 按权限申诉 |
| 早退 | 早退 | 申诉入口由政策开关决定 |
| 请假 | 请假 | 查看有效请假和同步状态 |
| 待处理 | 待核实 | 核对流程，不进入普通申诉快捷改判 |

未知原始值进入规则核验，不能自动视作正常。状态必须有文字，颜色只是辅助。

基础判定沿用基线：正常＋刷脸/istudy/二维码 → 正常；正常＋刷卡 → 旷课（D06 待确认）；正常＋空/未知方式 → 待处理；迟到/早退/旷课保留；其他未知结果 → 待处理。

最终结果由服务端按规则版本计算：有效人工结论优先并保护；否则仅基础旷课可由已批准、覆盖该人/日期/节次、撤销未确认的有效请假覆盖。请假不自动消除迟到、早退和待处理。重叠请假取并集；撤销一张不能无条件恢复旷课。前端只展示依据和结果。

## 2 四种状态不能共用一个 resolved

| 维度 | 例子 | 用途 |
|---|---|---|
| 考勤结果 | final_judgment 六类 | 业务事实与统计 |
| 工作项状态（本补充建议） | open / in_progress / completed | 未处理、跟进中、已完成 |
| 审批状态与阶段 | submitted/reviewing/approved/rejected；first/second/counselor | 权威审核流程 |
| 回写状态 | pending / applying / applied / failed | 批准是否已实际作用到考勤 |

工作项状态是配套建议，不新增可绕过基线的审批流程。“待核实”可能还在跟进；“旷课”也可能已有跟进记录。不能用任务完成等同出勤正常。

| 操作 | 工作项变化 | 是否改判 | 是否仍在待办 |
|---|---|---|---|
| 添加备注/已联系待跟进 | open → in_progress | 否 | 是，筛选“跟进中”可见 |
| 权限内确认到场/缺勤 | 提交后保留处理中；实际生效后 completed | 服务端产生有依据的人工结论 | 生效后才移出该核对队列 |
| 仅发起请假或申诉 | 原事项关联申请，不提前关闭 | 否 | 显示流程进度 |
| 终审批准但回写失败 | 不标全部完成 | 尚未生效 | 同步异常可见 |
| 服务端确认回写及相关流程完成 | completed | 按权威事件生效 | 可移出活动待办，历史保留 |
| 已完成后新来源/新证据冲突 | 新复核任务或授权重开，留痕 | 不静默覆盖 | 进入相应复核队列 |

原型“请假已核实”“签到问题已登记”不能直接完成正式核对。是否关闭某类跟进事项由该业务服务验证，不仅看一个下拉文本。

## 3 角色、动作与防自审

学生只能本人查询和发起申请；副班长/干部在授权班级范围处理相应核对/审核；辅导员按基线学院范围及负责班级路由；技术管理员不默认取得业务改判权。副班长和干部仍保留学生身份，可以拥有多个有期限范围。

本人核对和本人申诉审核均排除本人。本人是唯一审核人、角色过期或无人审批时转其他授权人/辅导员。旧页面提交必须重新授权，按钮隐藏不是控制措施。病假证据默认仅本人和对应辅导员查看。

核对动作是“确认到场/确认缺勤”，必填说明，可附证据；不是通用“已处理”。申诉默认仅旷课、迟到，早退由开关控制，待处理走核对。理由和证据必填，诉求固定正常，同一记录最多一张活动申诉。

## 4 审批、并发与时限

- 一审通过不改判；终审权威通过且回写成功后才展示实际更正。
- 七天一审时限：提交时刻＋7×24 小时；超过时限旧处理权失效，不能只靠定时扫描。
- 七天公示按实际更正生效起算（D16 待确认），保留原审批时间；期满普通流程锁定，仅辅导员带理由复核。
- 撤回必须使旧审批无法继续生效；不能取消时显示处理未完，不伪装已撤回。
- 每次写入携带 expected_revision；并发冲突保留输入但不覆盖别人新结果。幂等键只对应一次业务动作，重复提交返回同一受理结果。
- 迟到事件、重复事件、请假撤销和来源更正都不能静默冲掉有效人工结论或锁定结果。

## 5 统计口径

正式统计按一人一课一日一节计数。默认总量是身份有效且已入库的记录数，不由学生总人数乘课程数推算；异常为旷课＋迟到＋早退，待核实独立。旧“旷课＋待处理”只能另标“需关注”。

覆盖为 partial/unknown 时显示“已导入考勤/数据未齐”，不能用进度条称全院完整到课率。应到、请假分母、早退和迟到折算、去重人数均需业务确认；不把原型 96.7% 用作正式算法。

## 6 数据与消息

未导入、未匹配、无日期不是旷课。历史日期固定，不随 TODAY 或当前系统日期改变。业务时间统一 Asia/Shanghai。

个人日报一期纳入，默认北京时间 21:00；学生只收本人信息，辅导员汇总另做。数据未齐明确提示，当日无数据不发旧日报冒充今日。消息失败不回滚审批结果，unknown 回执先核对再决定补发。当前前端没有任何 IM 发送实现。
