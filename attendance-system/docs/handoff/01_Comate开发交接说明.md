# Comate 开发交接说明

v1.1｜2026-09-20｜前端复用交接，非生产验收报告。

## 接手目标与规模

在用户选定的暖白青绿前端上继续开发，复用布局与交互，把真实业务规则、身份、数据和工作流接到页面。学校 WPS 365 是业务平台，Comate 是实施工具。本期先 Excel，学校考勤 API 后续接入。

本期学院范围。既有设计引用约 2,432 名学生、66 个班、单周 31,792 行、学期约 60 万条；它们是已有文档的容量输入，未在本轮重新实测。原型的 1,280 行、4 个班只是展示样本。

## 本包真实完成情况

| 内容 | 当前状态 | 如何复用 |
|---|---|---|
| 暖白青绿、顶部导航、指标区、异常表、班级进度条 | 已实现，用户已选风格 | 后续页面视觉依据 |
| 工作台、考勤记录、异常处理、统计报表 | 同一 React 页面中的四个视图 | 不是完整多页业务系统，没有路由守卫 |
| 搜索、筛选、5 行分页、详情弹窗 | 浏览器演示验证通过 | 复用交互，正式版改服务端查询分页 |
| 处理备注、移出待办、历史可查 | 仅当前会话演示 | resolved 简化逻辑必须替换，不是正式核对或审批 |
| CSV 导出 | 演示文件实际下载并核验 | 增加范围授权、跨分页完整性和大文件任务 |
| 身份、角色权限、API、后台持久化、审批、消息 | 尚未实现 | 头像与按钮不证明已有这些能力 |
| docs/contracts 类型及 JSON | 本轮新增声明性设计 | 未被运行时导入，不能称适配器已完成 |

design-qa.md 的 passed 仅指演示界面的视觉与已测交互。本轮未改 UI；正式业务、正式租户验收仍未完成。

## 已知问题：应进入 Comate 任务单

- resolve 对所有结果设 resolved=true，连“待后续跟进”也移出列表。
- pending 将全部未处理的非正常记录混成一个队列；正式待核实核对与旷课/迟到申诉不同。
- “请假已核实”是备注选项，无审批实例、批准证据或考勤回写。
- “未到”无原始结果/方式支撑，不能直接视为旷课。
- 全部数据先加载到浏览器，再筛选分页；不能照搬到几十万行。
- 无服务端授权、版本冲突、幂等、错误恢复、持久任务和审计。
- 日期、更新时间、用户名字固定；正式版按查询日期、服务端时间和认证身份展示。
- 原型按模拟人头统计；正式一条事实是一人一课一日一节，人数、记录数、节次不得混标。

## 实施顺序

| 接续任务 | 原阶段 | 阶段出口 |
|---|---|---|
| FE-A 工程盘点、能力与字段映射 | A | 可运行基线、差异表、真实与未知能力分列 |
| FE-B 组件、身份数据边界、六类 mock 和错误态 | B/C | mock/真实 provider 可替换，权限不足和同步中可演示 |
| FE-C Excel、查询、待核实核对 | B/C | 权限、分页、幂等导入、写回和统计一致 |
| FE-D 请假申诉连接原生流程 | D | 审批与同步分离、防自审、时限和锁定成立 |
| FE-E 看板、IM 入口与失败台账 | E | 范围、覆盖、更新时间明确；测试白名单联调 |
| FE-F 联调与交付 | F | 两份验收清单、真实证据、部署回滚备份说明 |

学校考勤 API 后续接入时增加采集适配器，仍走同一校验、去重、原始版本、判定和汇总链路，不能形成另一套最终事实。当前集中 mock 文件只是便于替换，不是已实现 API 模块。

用户后续明确要求优先；已确认视觉与既有业务设计分别约束外观和行为。契约是配套实现建议，不自行改变业务政策；mock 和截图只能作示例。
