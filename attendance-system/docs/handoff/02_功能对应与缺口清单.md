## 原型语义与正式业务的差异

| 原型 | 正式含义 | 改造要求 |
|---|---|---|
| 未到 | 不能判断等同旷课 | 重读 raw_result/raw_way，服务端判定 |
| 待处理异常 64 | 演示中未到＋迟到待办 | 核对、异常、跟进事项分别计数 |
| 应到人数/实到人数 | 模拟单次人头 | 正式默认已导入节次及分类；人数必须去重和标口径 |
| resolved | 简化“处理过” | 最终结果、任务、审批、同步四类状态分开 |
| 请假已核实 | 备注 | 无批准效力，须可信批准单和回写 |
| 导出报表 | 实际为明细 CSV | 正式明确“明细”或“汇总”，避免名实不符 |

现有原生表单/审批可通过受控链接或经验证的内嵌接入，不要求再造可写审批系统。当前四个导航不是完整信息架构；按角色扩展入口时沿用已确认风格。
