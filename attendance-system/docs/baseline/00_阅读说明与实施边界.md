# 课堂考勤管理系统 Comate 设计实施包

版本：v1.0｜日期：2026-09-19｜状态：供业务评审和 Comate 实施使用的设计稿

本材料定义如何基于学校已有 WPS 365 建设学院课堂考勤管理应用。它不是现有系统的验收报告，也不代表下述接口已在学校租户验证。

| 文件 | 用途 | 主要读者 |
|---|---|---|
| 01_总体设计与建设范围.md | 定位、平台分工、已有样例复用、一期范围、设计决策 | Simon、学院负责人、Comate |
| 02_数据模型与字段字典.md | 建表、字段类型、主键、关联、历史数据和统计口径 | Comate |

## 依据及优先级

1. 用户本轮明确条件：全校已使用 WPS 365，已有统一通讯录、表单、支持超过 100 万行的多维表格、轻审批、IM；由本材料负责设计，Comate 负责实施。
2. 《课堂考勤系统需求文档-v4业务基线.docx》：沿用业务角色、主要判定规则、请假和申诉机制；其中独立数据库、放弃多维表格的技术结论不作为本轮约束。
3. 本轮 7 张样例截图：用于理解已有表和视图，不等于已取得表结构、公式、权限配置或真实生产数据。
4. 本轮设计建议：特别是学生日报纳入一期、账户映射、历史留存、状态优先级和可靠性机制。所有业务口径变更在 01 的决策表中显式标记。

本包没有获得现网访问权限、Comate 工程、应用凭证、官方租户接口文档或真实 Excel 数据文件。文档中出现的数量来自 v4 的自述；验收文件全部是“待执行”。

## 使用约定

- WPS 365 是运行依赖和业务平台；Comate 是实施工具。Comate 能编写代码并不自动提供生产部署、调度、凭证和运维环境。
- 本期覆盖电信学院；组织与字段预留其他学院。全校账户已统一不等于已授权全校推广本应用。
- WPS 原生能力优先，扩展代码补充规则和联动；不因旧文档的历史平台限制，默认重建独立账户、审批或数据库。
- 所有表名、字段名和适配方法名均为本设计的逻辑命名，不是声称存在的 WPS API 路径或字段 ID。
- 不直接修改现有样例或生产表。先在隔离的开发空间建立映射与脱敏样例；字段 ID、审批模板 ID、应用 ID 由 Comate 实测取得。
- 对待定业务规则可在测试环境使用明确标注的默认值推进；在业务确认前，不对真实学生启用这些规则的自动改判与消息推送。其余工作正常推进。
- 日期和业务定时统一 Asia/Shanghai；存储时间须含时区或使用 UTC 时间戳，展示转北京时间。

## 交付完成的含义

只有真实租户上的身份、权限、表单、审批、考勤更正、统计和 IM 全链路通过验收，才能标为“已完成”。仅有页面、模拟接口返回、审批通过截图或测试数量，不能代替真实业务验收。

本设计包不包含可执行系统代码，也没有进行任何生产配置、审批或消息发送。
