# 多维表格数据模型与字段字典

本文定义逻辑模型。实际多维表格字段类型、关联字段能力和 API 字段 ID 由 Comate 在本校租户验证后映射；不得把逻辑字段名直接当作官方接口字段。

## 1 数据设计约定

- 业务唯一标识使用应用生成的不可变字符串 ID；平台 record_id 单独保存。表格行号不能作为业务主键。
- ID/学号为文本，保留前导零；时间为带时区的时间戳；业务日期为固定日期；节次归一为 1—12 的单个整数。
- 下表中“唯一”是必须实现的逻辑约束，不假设多维表格原生强制唯一。写入服务串行化相关操作并维护去重索引；具体机制见 04。
- 人员显示名仅用于展示。授权使用 WPS 租户范围内稳定用户 ID、学生 ID、班级 ID 和有期限的角色范围。
- 默认按学院＋学期组织考勤明细；达到实测性能或容量阈值时再按月份分区，分区目录统一路由。请假和申诉引用业务 ID，不绑定某张物理表。
- 所有生产表增加 tenant_id；学院级数据增加 college_id。归档表仍保留业务 ID 和权限，不能以归档为由关闭正在处理的申诉。

## 2 表与唯一关系

| 逻辑表 | 一条记录代表什么 | 逻辑唯一约束 | 首选来源或写入者 |
|---|---|---|---|
| student_profile 学生档案 | 一名学生的稳定身份 | tenant_id＋student_no；student_id 唯一 | 权威名册同步 |
| identity_link 账号映射 | 一个学生身份对应一个租户账号 | tenant_id＋wps_user_id；student_id | 经核验的通讯录与名册映射 |
| class_profile 班级档案 | 一个班级 | tenant_id＋class_id | 现有班级表 |
| student_class 学生班级关系 | 一段有效期内的班级归属 | membership_id；有效期不得冲突 | 名册或经审核更正 |
| role_assignment 角色授权 | 某人对某范围拥有某角色 | assignment_id；角色＋人员＋范围＋有效期不重复 | 授权辅导员/管理员 |
| course_session 课程课次 | 某班某日某节的具体课程 | session_id；班级＋日期＋节次＋课程标识 | 课表或导入补建 |
| enrollment 学生选课关系 | 学生在有效期内参加一门课程/教学班 | enrollment_id | 现有学生课程总表，可选 |
| import_batch 导入批次 | 一次文件接收及处理过程 | batch_id；file_hash 用于文件去重提示 | 导入服务 |
| raw_attendance 原始考勤 | 一个来源逻辑键的一个内容版本 | source_key＋payload_hash | 导入服务，只增不改 |
| attendance 考勤明细 | 一名学生一日某课程某节的考勤 | attendance_id；business_key | 统一考勤写入服务 |
| leave_request 请假主单 | 一次请假申请和审批关系 | leave_id；external_instance_id | 表单受理/审批同步服务 |
| leave_member 请假人员 | 某请假单覆盖一名学生 | leave_id＋student_id | 请假受理服务 |
| appeal 申诉单 | 对一条考勤的一次申诉 | appeal_id；同考勤最多一张活动申诉 | 申诉服务 |
| review_event 判定事件 | 一次核对、人工改判或撤销人工结论 | event_id | 授权审核服务，只增不改 |
| daily_stat 日统计 | 日期、范围、结果类别的一项计数 | scope_type＋scope_id＋date＋judgment | 汇总服务 |
| event_job 事件任务 | 一项尚需执行或已执行的业务动作 | idempotency_key | 持久任务处理器 |
| notification 消息台账 | 发给某人的一项通知 | message_key | 通知服务 |
| audit_log 操作审计 | 一次业务动作或权限变更 | audit_id | 应用与平台审计汇集 |
| data_partition 分区目录 | 一个学院学期数据分区的位置 | partition_id | 部署配置或管理员 |

以上是逻辑分表，是否合并部分辅助表由实测决定。考勤明细、原始记录、审批单及发送台账不合并成一张大表；任务表也可落在经核验的持久任务运行支撑中。

## 3 身份与组织字段

### student_profile

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| student_id | 文本 | 是 | 应用稳定 ID |
| tenant_id / college_id | 文本 | 是 | 租户和学院范围 |
| student_no | 文本 | 是 | 学号；没有学号的原始行先进入映射异常，不建立可登录的临时学生 |
| name | 文本 | 是 | 权威名册姓名 |
| current_class_id | 关联/文本 | 是 | 当前班级，用于展示；历史按有效期关系查 |
| active | 布尔 | 是 | 在校/启用状态，不删除历史 |
| source / source_updated_at | 文本/时间 | 是 | 来源及更新时间 |

identity_link 字段：link_id、tenant_id、student_id、wps_user_id、directory_object_id、link_status（verified/unresolved/conflict/disabled）、verified_by、verified_at、source。具体 WPS ID 语义由身份适配器验证，不把 openid、unionid 和 IM 用户 ID 混用。

class_profile 字段：class_id、tenant_id、college_id、class_name、grade、active。student_class 字段：membership_id、student_id、class_id、valid_from、valid_to。历史考勤保存发生时班级快照，转班后不自动迁移历史统计。

role_assignment 字段：assignment_id、wps_user_id、role（student/monitor/student_cadre/counselor/admin）、scope_type（self/class/college）、scope_id、valid_from、valid_to、enabled、assigned_by。副班长和干部继承本人学生能力；技术管理员不默认拥有考勤改判权限。角色允许多个范围，避免旧版单字段不能表达跨班代审的问题。

## 4 课程与日期字段

course_session 字段：session_id、tenant_id、college_id、term_id、class_id、teaching_group_id（可选）、course_id（可选）、course_name、teacher_name、teacher_user_id（可选）、att_date、period、source_period_text、room、week、course_type、source、schedule_status。

“1—4 节”若经来源定义确认代表连续四节，拆成四个课次；请假覆盖和考勤统计按节计算。若学校文件每行已代表单节，则不再展开。若一条签到只覆盖一场四节连堂课、无法证明覆盖各节，标记粒度待确认，禁止直接复制成四条正常。

enrollment 字段：enrollment_id、student_id、course_id/teaching_group_id、valid_from、valid_to、source。课程表不足时仍允许以学校考勤明细为一期输入；不得因“课表没有匹配到”删除学校已有考勤，也不得仅凭缺少导入行认定缺勤。

## 5 导入和考勤字段

import_batch：batch_id、file_name、file_hash、source_system、term_id、date_from、date_to、total_rows、valid_rows、inserted_rows、duplicate_rows、conflict_rows、unmatched_rows、invalid_rows、status（received/validating/processing/completed/partial/failed）、checkpoint、operator_id、started_at、completed_at、error_report_ref、coverage_status（unknown/partial/complete）、coverage_confirmed_by。

raw_attendance：raw_id、batch_id、source_row_number、source_key、payload_hash、source_record_id（如有）、name_raw、class_raw、course_raw、teacher_raw、period_raw、room_raw、week_raw、sign_time_raw、raw_result、raw_way、att_date_raw、ingested_at、validation_status。原始附件受限存放，记录文件摘要和版本。

attendance 主事实表：

| 字段 | 类型 | 必填 | 用途 |
|---|---|---|---|
| attendance_id / business_key | 文本 | 是 | 稳定引用与逻辑去重 |
| tenant_id / college_id / term_id | 文本 | 是 | 隔离与分区 |
| student_id / student_no_snapshot | 关联/文本 | 是 | 人员和发生时学号 |
| name_snapshot / class_id / class_name_snapshot | 文本 | 是 | 历史显示与统计归属 |
| session_id | 关联/文本 | 否 | 可对应的课次；无法确认时保留为空并说明 |
| course_name / teacher / room / week | 文本或数字 | 依来源 | 来源快照 |
| att_date / period | 日期/整数 | 是 | 明确到某日某节 |
| raw_id / batch_id | 关联/文本 | 是 | 当前生效来源版本 |
| raw_result / raw_way / sign_time | 文本/时间 | 依来源 | 原始值，不用人工结论覆盖 |
| base_judgment | 枚举 | 是 | 正常/旷课/迟到/早退/待处理 |
| leave_ids | 多关联/文本集合 | 否 | 当前命中的所有已批准请假单 |
| manual_judgment / manual_event_id | 枚举/文本 | 否 | 有效人工结论及事件 |
| final_judgment | 枚举 | 是 | 正常/旷课/迟到/早退/请假/待处理 |
| judgment_reason / rule_version | 文本 | 是 | 判定解释与规则版本 |
| business_revision | 整数 | 是 | 每次生效变更递增，用于并发控制 |
| public_until / locked_at | 时间 | 否 | 申诉成立后的七天公示与锁定 |
| last_appeal_id | 文本 | 否 | 最近申诉；不替代独立申诉历史 |
| applied_event_id / updated_at | 文本/时间 | 是 | 防重复生效及追溯 |

正常已映射行的 business_key = tenant_id＋term_id＋student_id＋发生时班级 ID＋att_date＋period＋规范课程标识。课程无稳定 ID 时采用经确认的课程名称映射；名称变化引起的键冲突进入复核。未映射行保留在原始表/异常队列，不生成可能归错人的正式考勤。

同键同内容：重复跳过；同键不同内容：新增原始版本并进入来源变更复核，默认不静默覆盖人工结论或已公示结果。若学校更正文件有明确版本顺序，方可按确认的策略自动采用新来源版本。

## 6 请假与申诉字段

leave_request：leave_id、applicant_user_id、on_behalf（布尔）、leave_type（public/sick/personal/other）、start_date、end_date、periods（空代表全天，否则规范整数集合）、reason、evidence_refs、external_instance_id、approval_template_version、approval_status（draft/submitted/approved/rejected/cancelled）、approval_version、apply_status（pending/applying/applied/failed）、approved_at、revoke_status（none/requested/confirmed/rejected）、revoke_instance_id、revoked_at、created_at、updated_at。

leave_member：leave_id、student_id、student_no_snapshot、class_id_snapshot、apply_status、affected_record_count。不同学生各自生效；多人公假部分失败时不能把整单标为全部已应用。

病假佐证必须有受限附件引用；附件不得成为无鉴权公开链接。请假撤销待确认时，原请假仍有效。审批通过而回写未完成时，页面显示“审批通过，考勤同步中/同步异常”。

appeal：appeal_id、attendance_id、student_id、applicant_user_id、reason、evidence_refs、requested_judgment（固定正常）、original_judgment、original_revision、status（submitted/reviewing/approved/rejected/withdrawn/locked）、stage（first/second/counselor/done）、first_deadline、reviewer_scope、external_instance_id、approval_template_version、source_approval_version、apply_status、final_at、public_until、locked_at、created_at。

进行中申诉包含 submitted/reviewing，以及 approved 但尚未完成结果回写的单据。公示期内同记录不新开平行申诉；学生有新异议通过“联系辅导员/申请复核”提交说明。终审通过且实际更正成功后开始七天公示，若两者不同时，以实际业务生效时点为准并保留审批时间。这是为异步回写增加的设计口径，需业务方确认。

review_event：event_id、attendance_id、action（pending_confirm/manual_override/appeal_apply/manual_revoke）、from_judgment、to_judgment、before_revision、after_revision、reason、evidence_refs、operator_user_id、related_request_id、created_at、active。撤销人工结论用新事件，不删除原事件。

## 7 汇总、通知和辅助字段

daily_stat：stat_key、scope_type（student/class/college）、scope_id、att_date、judgment、count、source_watermark、reconciliation_status、last_rebuilt_at。个人、班级和学院汇总来自同一事实表；不用学生课程总表的行数当考勤总数。

统计口径：总节次为该范围已入库且身份有效的考勤记录数；异常节次默认旷课＋迟到＋早退；待核实单列。覆盖率未知时称“已导入考勤”，不称全院完整到课率。确需展示 v4“旷课＋待处理”口径时，单独命名“需关注记录”，不能混为同一个异常率。

event_job：event_id、idempotency_key、entity_type、entity_id、event_type、source_version、status（queued/running/succeeded/retry/dead）、payload_ref、attempts、next_retry_at、lease_owner、lease_until、checkpoint、last_error、created_at、finished_at。

notification：notification_id、message_key、receiver_user_id、student_id（可空）、kind、business_date、business_ref、summary_version、payload_ref、status（queued/sending/sent/failed/unknown/skipped）、attempts、next_retry_at、platform_message_id、last_error、sent_at。unknown 表示请求结果不明，必须核对后再决定是否重发。

audit_log：audit_id、actor_user_id、actor_role_snapshot、scope_snapshot、action、entity_id、before_ref、after_ref、reason、source_event_id、result、occurred_at。凭证和完整病历内容不得写入普通审计日志。

data_partition：partition_id、tenant_id、college_id、term_id、date_from、date_to、logical_table、workspace_ref、table_ref、schema_version、status、retention_policy、last_backup_at。实际资源标识在部署配置中填写。

## 8 历史迁移和样例处理

1. 只读盘点已有表 ID、字段 ID、公式、关联、权限、自动化和记录数量，形成映射清单。
2. 将样例标记为 demo；开发环境复用脱敏结构，不把示例签到、示例请假混进生产统计。
3. 保留课程和人员关系；使用账号 ID 和学号校验，姓名匹配只作候选。
4. 原有“今日”公式作为视图条件保留，正式考勤生成时写入固定日期、来源和判定版本。
5. 历史请假只有可核验审批证据、申请人和日期节次均可映射时才迁移为有效；其余仅保留历史记录并标待核验。
6. 按小批次迁移，核对来源数、有效数、重复数、异常数以及分类总数，再切换入口；可按批次回退导入结果，不能回退已发生的独立审批动作。
