# 接口验证与 Comate 实施任务

本文件给出实施契约和任务顺序，不声称特定接口已可用。方法名均为应用内部适配器方法，实际 WPS SDK、HTTP 路径、权限 scope、字段 ID 由实施时查证。

## 1 平台能力验证清单

| 编号 | 验证对象 | 最小验证动作 | 必须记录的证据 |
|---|---|---|---|
| P01 | 当前登录身份 | 用学生和辅导员账号各获取自身身份；无登录请求应被拒绝 | 用户 ID 类型、租户范围、令牌用途和权限 |
| P02 | 通讯录与学号 | 读取授权范围的测试用户及扩展字段，与名册匹配 | 学号/班级是否存在、缺失清单、映射依据 |
| P03 | 多维表格结构 | 读取样例表结构、关联和公式，创建隔离测试表 | workspace/table/field 的真实标识映射 |
| P04 | 查询与分页 | 建超一页数据，遍历并比对总数；按人员和日期筛选 | 分页参数、终止条件、单页上限、筛选支持 |
| P05 | 写入和并发 | 创建、更新、重复写入、同时更新同一行 | 批量上限、返回错误、幂等支持、条件更新能力 |
| P06 | 行与附件权限 | 两名学生互访、URL 改 ID、导出、展开关联字段、附件访问 | 可访问/拒绝证据与平台配置 |
| P07 | 表单身份 | 登录提交后验证作者身份；尝试修改姓名/学号和重复提交 | 可信身份来源、提交事件、附件引用 |
| P08 | 轻审批路由 | 发起测试单，动态选人，排除本人，无人时路由辅导员 | 模板字段、实例 ID、审批人选择方式 |
| P09 | 审批状态回传 | 通过、驳回、撤回、重复和延迟事件；查询状态 | 回调验真方式或查询接口、版本/顺序字段 |
| P10 | 转办和撤销 | 一审超时换人，旧审核页再提交；撤销通过的请假 | 平台是否能取消旧任务、实例状态终结规则 |
| P11 | IM 消息 | 发给白名单测试账号，验证身份、链接、失败和回执 | 接收人 ID、授权、限额、幂等/查询能力 |
| P12 | 调度运行 | 测试定时任务，重启后恢复；验证时区和日志 | 运行环境、持久化、重试、监控归属 |
| P13 | 容量与性能 | 按 31,792 行、60 万行及百万行级代表数据逐级测试 | 实际行数、索引/筛选、读写耗时、失败率、平台配额 |
| P14 | 备份和恢复 | 导出小型测试分区并在隔离环境恢复 | 记录数、附件可用性、业务 ID、权限和关联校验 |

以上验证不需要一开始都阻塞开发。P01/P02 决定身份方案；P04/P05/P06 决定数据访问方案；P08—P10 决定审批集成方案；其他任务可在清晰标注模拟接口的条件下并行推进。真实生产接通之前必须验证其依赖。

## 2 官方资料与证据边界

检索入口：[WPS 开放平台](https://open.wps.cn/)。本次访问该官方入口未取得可核验的具体接口参数；旧金山文档开放平台入口亦跳转到该平台。因此本设计没有编造 WPS 接口路径、固定批量上限或审批回调能力。

平台已有通讯录、表单、多维表格、轻审批和 IM，以及多维表格超过 100 万行的容量，均采用用户提供的现网前提。接口性能、原生权限粒度、审批动态路由、回调和消息额度，由 Comate 在学校授权环境形成实际证据；不能援引其他厂商相似接口替代验证。

## 3 适配器契约

| 逻辑适配器 | 输入与操作 | 输出与错误处理 |
|---|---|---|
| Identity.resolveCurrentUser | 已验证登录凭据 | tenant_id、stable_user_id、组织信息；失效或无权限则拒绝 |
| Directory.listUsers | 范围、分页游标 | 用户列表、下一页标记；不以显示名作为主键 |
| Table.query | 逻辑表、授权筛选、字段集、分页参数 | records、next_cursor/has_more；分页方式按实际接口 |
| Table.createBatch | 规范记录、幂等标识 | 每条成功/失败与 record_id；部分成功不能只返回整批成功 |
| Table.updateRecord | record_id、变化字段、预期业务版本 | 新版本；无平台条件更新时由串行服务保证，不伪装为原子操作 |
| Form.acceptSubmission | 来源表单、可信提交人、submission_id、数据、附件 | 本地业务单号；重复提交返回已有单号 |
| Approval.start | 模板版本、申请人、路由范围、业务单号 | 实例 ID；请求结果不明时先查询关联实例，不能盲重建 |
| Approval.fetchState | 实例 ID、已处理版本 | 权威状态、节点、审批人、结果时间与版本证据 |
| Approval.changeRoute | 实例 ID、旧任务、新处理人、理由 | 确认旧任务失效或返回不支持；不支持时明确替代流程 |
| Approval.receiveEvent | 可验证来源事件或服务端查证后的状态 | 标准事件 ID、实例 ID、状态、版本；不能信任前端提交的“已批准” |
| Message.send | 接收人 ID、消息种类、内容、跳转、去重键 | message_id/明确失败/结果未知；支持时带平台幂等键 |
| Scheduler.enqueue | 持久任务、执行时间、幂等键 | job_id；重启不丢任务 |

标准事件包含：event_id、event_type、entity_id、source_instance_id、source_version、occurred_at、received_at、actor_id、payload_ref。平台没有事件 ID/版本时，适配器以查得的权威状态和受控快照产生稳定摘要；不得仅使用到达时间判断审批新旧。

## 4 审批集成分级方案

优先级 A：原生轻审批支持动态路由及可验证结果回传，直接复用一个完整实例。

优先级 B：可查询权威状态但无回调，采用持久轮询与对账。界面明确更新时间，轮询间隔受配额限制，后台可配置。不得承诺实时。

优先级 C：轻审批不支持动态二级路由，但支持可靠创建、结束、查询单级实例，可以采用业务服务编排两个顺序实例；各级审核仍在轻审批，业务服务维护唯一下一阶段和版本。此为条件设计，需先证明实例不能并行重复生效。

如果没有可靠的结果读取，或无法使超时旧审批失效，就不宣称全自动流程完成。实施报告记录缺口，完成其他模块并提交明确的范围变更建议。临时人工确认方式必须标为过渡流程，不能以多维表格手填“通过”伪装成轻审批集成成功。

## 5 写入一致性与任务恢复

### 5.1 单一写入路径

最终判定、审批结果投影、汇总、角色授权只由受控服务写入。原生表单和审批发出受理/审核事件；人员不能直接改受控字段绕过服务。所有写入通过同一逻辑服务，角色范围和当前记录版本由服务端校验。

### 5.2 先持久受理，再逐步生效

1. 对已验证事件写入持久任务，以幂等键识别是否已受理。
2. 同一考勤 ID 或申请 ID 采用单写者串行处理；拿到可靠租约/锁后读取最新版本。
3. 校验事件顺序、权限、原始版本、人工结论保护和公示锁定。
4. 更新考勤记录中的最终值、business_revision 和 applied_event_id，记录检查点。
5. 生成审计事件并按受影响范围重算汇总，或用已证明可去重的增量方式更新。
6. 创建待通知记录，标记任务成功。通知发送独立执行。

若多维表格不提供原子锁/条件更新，不能用“先查后插”冒充并发安全。默认单活动写入工作者，禁止多副本同时写；部署和故障切换须能保证唯一活动者。需要多副本时采用真实支持原子操作的任务/锁支撑，其选型由部署环境决定。

持久任务不能只是进程内数组或定时器。写入响应超时后先读取目标状态核对 applied_event_id 和版本，再决定续做。查询暂未可见时进行有限重试；平台读后写一致性不满足要求时，调整架构并记录结果，不能直接再插入一条。

### 5.3 对账与部分失败

- 发现明细已更正但任务未成功：依据 applied_event_id 补齐审计、汇总和通知，不重复改判。
- 汇总按受影响日期和范围从明细重算可重复执行；有多个并发变化时以水位判断是否需要再次重建。
- 通知台账以业务版本去重；一次失败不回滚考勤和审批。网络超时导致结果未知时，支持消息查询则先核对；不支持则保留 unknown 供管理员决定是否补发，不承诺严格一次送达。
- 非事务平台不能保证所有表在每一毫秒完全一致。显示同步状态，事件完成并对账后必须一致；审批已通过但同步失败不应显示“全部完成”。
- 定期扫描未处理批准结果、未完成任务、统计差异和未发送通知，形成可重试队列。需要人工修复的任务进入 dead 状态并给出业务原因。

## 6 性能与可靠性验收建议

以下是本设计建议的验收目标，不是厂商性能承诺。阶段 A 实测后冻结测试环境、数据量、权限、并发和目标；若需要调整须说明证据。

| 场景 | 建议验收目标 |
|---|---|
| 学生查询/管理筛选 | 60 万条背景数据、30 个并发查询用户时，端到端 P95 ≤ 3 秒 |
| 单周文件导入 | 31,792 行在 15 分钟内完成处理和汇总，错误可定位且可续传 |
| 审核生效 | 回调模式正常情况下 60 秒内同步；轮询模式按确认的轮询窗口验收 |
| 个人日报 | 学院约 2,432 人，21:00 启动后建议 30 分钟内完成或记录所有失败/跳过 |
| 一审超时扫描 | 建议每 10 分钟；接口提交仍实时检查截止时刻，不能依赖扫描才拒绝过期操作 |
| 台账对账 | 每次批次处理后对账，夜间完整检查；任何差异有责任队列 |
| 备份恢复 | 初始建议每日备份、恢复点不超过 24 小时；实际频率与恢复时长由学校确认 |

容量验收至少验证一个真实业务量级（60 万行），并用百万行级代表数据验证已选查询方式；不要求先全校生产导入。禁止每次打开页面拉取全部记录到浏览器后筛选。

## 7 分阶段实施任务

| 阶段 | 任务 | 依赖 | 必须交付 | 通过条件 |
|---|---|---|---|---|
| A 能力与样例盘点 | 平台权限、接口、表结构、公式、身份和审批验证 | 测试租户/空间、账号和接口资料 | capability_matrix、schema_mapping、差异与决策清单 | 关键能力有证据，未知项有替代方案 |
| B 身份与数据基础 | 学生/班级/角色、课程、导入、历史模型、数据权限 | A 的身份与数据验证 | 可重跑建表配置、映射表、导入报告 | 学生身份正确，重复导入无重复，越权被拒绝 |
| C 核定与查询 | 规则引擎、待处理、个人页面、汇总 | B | 规则版本、查询页面、测试 | 判定和权限用例通过，历史日期稳定 |
| D 请假与申诉 | 表单、轻审批、事件、撤销、防自审、超时、公示 | A 审批能力及 C | 审批模板、实例映射、事件恢复记录 | 真实审批改变考勤，重复事件不重复生效 |
| E 消息与管理 | 个人日报、结果通知、管理日报、失败重试和看板 | C/D；可先用测试消息接入 | 消息模板、定时任务、看板 | 只发本人或授权管理员，不重复、不冒充完整数据 |
| F 试点与交付 | 一到两个班小范围试用，性能、恢复、业务验收 | B—E | 验收报告、操作手册、部署/回滚/备份说明 | 用例证据齐全，待确认业务规则已冻结 |

每阶段结束由 Comate 输出：完成项、真实验证证据、未完成项、影响范围、下一步。模拟通过和真实租户通过分列；不以测试函数数量代替业务完成度。
