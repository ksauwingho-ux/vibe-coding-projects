# Comate 启动指令与分阶段任务

## 总指令

复制以下内容，并将本包全部文件提供给 Comate：

```text
你是本项目的实施工程师。请依据附件“课堂考勤管理系统 Comate 设计实施包 v1.0”实施一套基于学校现有 WPS 365 的课堂考勤管理应用。

已知条件：全校已使用 WPS 365，有统一通讯录、表单、支持超过 100 万行的多维表格、轻审批、IM。本期业务范围为电子与通信工程学院，参考规模约 2,432 名学生、66 个班、一学期约 60 万条考勤。已有多维表格场景和截图可复用。

实施原则：
1. 读取 00—06 全部材料，以本包的逻辑模型、规则、任务及验收为准。v4 旧文档是业务参考，不沿用其中默认放弃多维表格、重建 SQLite 及独立账户的技术路线。
2. 优先复用 WPS 身份、多维表格、表单、轻审批、IM 和原生视图；开发规则、数据联动、权限适配、历史记录、页面和可靠任务。不要重建整套协作平台。
3. 先盘点本环境真正可用的接口和授权。材料里的适配器名、字段名是逻辑设计，不是 WPS 官方 API。禁止猜造接口、批量上限、行权限或回调能力。
4. 先在隔离测试空间开发，保留现有样例和生产数据。记录 sample/demo 与真实数据边界；消息默认仅发测试白名单。
5. 学生身份使用可信 WPS 用户 ID 与学号映射；不以手填姓名或手机号后四位作为生产登录凭据。姓名加班级只用于旧 Excel 的匹配候选。
6. 最终考勤结果统一由受控写入服务产生，保留原始数据、业务版本、人工结论和审计。不能让表格公式、手工编辑和审批自动化互相覆盖最终值。
7. 轻审批处理审核过程；审批结果投影与考勤回写状态分别保存，处理重复、延迟和乱序事件。接口不足时给出证据与条件方案，不静默替换架构。
8. 学生个人每日考勤通知属于一期；辅导员日报另做。不能用群发全班明细替代每人只收本人信息。
9. 待业务确认的规则使用明确标注的测试默认值推进；不得将未确认政策直接用于真实学生自动改判。必要的字段 ID、接口和环境缺口列为资源清单，能独立推进的开发继续完成。
10. 请按阶段 A—F 实施。每个阶段交付可运行成果、配置清单、已执行验收证据、未完成项及原因。模拟接口通过不等于生产联调通过；不捏造“已完成”状态。

现在先执行阶段 A：盘点现有工程、WPS 能力和样例资源，输出真实的 capability_matrix 与 schema_mapping，并以最小测试数据验证身份、多维表格查询写入及审批结果读取。没有权限的项标为待验证，不调用真实学生消息或改生产数据。随后按已验证能力推进阶段 B。
```

## 分阶段追加指令

### A 平台能力与现有样例

```text
请完成 04 中 P01—P12 的最小验证或明确记录缺口。对现有样例只读盘点，重点检查“今日日期/今日课程/是否需要打卡/打卡状态/考勤情况确认”的公式与数据来源。
输出：能力矩阵（能力、真实接口/连接器、权限、验证步骤、结果、证据、限制）、逻辑字段到真实表字段的映射、现有样例复用清单、需要业务确认的规则。不要仅凭产品名称声称接口可用。
```

### B 数据和身份

```text
请按 02 创建测试环境数据结构，完成 WPS 账号与学号映射、班级关系、角色范围和考勤 Excel 导入。处理重复文件、同键更正、同名、未匹配、节次范围和历史日期。
输出可重跑的建表配置或脚本、导入预览和错误报告。用两名学生、一名副班长、一名干部、一名辅导员的虚构数据验证数据隔离。未经确认不得导入截图中的真实学生姓名作为测试人。
```

### C 判定和查询

```text
请按 03 实现基础规则、请假覆盖和人工结论保护；当前尚未接入审批的部分使用明确标注的模拟事件。完成我的考勤、考勤详情、本班待处理、汇总视图。
从 05 选择相应验收用例执行，保留输入、实际输出和证据。若没有 v4 的真实 31,792 行文件，真实数据回归必须标为未执行。
```

### D 请假和申诉

```text
请接通 WPS 表单和轻审批，实现请假、多人公假、撤销、申诉两级审核、防自审、七天一审时限、辅导员代审、七天公示和结果锁定。
同时实现事件去重、版本校验、同步状态与恢复。重点演示同一批准事件收到两次只生效一次、先请假后导入、两张请假撤销一张、旧审批页面超时后提交被拒绝。原生流程能力不足时先说明真实缺口及适配方案。
```

### E 消息和看板

```text
请接通测试白名单 IM，完成北京时间 21:00 的学生个人日报和辅导员汇总，增加审批/核对结果及待办消息。没有当日数据不能发旧日报冒充今日，数据未齐要注明。
演示失败重试、结果未知处理、错误身份不发送和无重复日报。看板使用汇总台账，展示异常与待核实的独立口径和数据更新时间。
```

### F 验收和运行交付

```text
请完整执行 05 验收用例，实际状态只使用通过、失败、阻塞、未执行，并附证据。按 04 做代表性容量、查询、导入、恢复验证。
交付工程、部署配置、平台资源清单、接口和字段映射、审批模板版本、操作手册、备份恢复步骤、验收报告及已知限制。进入真实班级试点前，列出已确认规则和未确认规则；未确认项不得伪装成已验收。
```
